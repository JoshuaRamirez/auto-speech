# auto-speech v0.3.0 — speech yields to other apps' sound

**Date:** 2026-10-18 · **Baseline:** `v0.2.0` · **Commits:** `e91a3c4..e91ea72 (plus this release-notes commit)`,
merged to `main` by a `--no-ff` merge of `worktree/sound-yield` · **Tests:** `tests/run_all.sh` 52 test files ran, 0 failed (630 counted unit tests plus the shell suites), under the isolated runner

## What changed for you

**Speech no longer plays over your music.** When another app is playing
sound, auto-speech holds its speech, keeps its place in the queue, and
speaks once the sound stops. If the sound carries on past three minutes
the held speech is dropped and the daemon log says so; autoplay audio is
still in the replay cache for `/auto-speech-replay`.

**You can name exceptions, and you can switch it off**, with the same
words in three places:

| Surface | How |
|---|---|
| CLI | `auto-speech yield add Music Spotify`, `yield off`, `yield status`, `yield check` |
| MCP | `sound_yield(action="add", apps=["com.apple.Music"])` |
| Config | `~/.config/auto-speech/sound-yield.toml`, `[sound_yield]` |

A change takes effect at the next playback, or at the next poll of a hold
already in progress. No restart.

**Nothing new to grant.** Detection is a Core Audio property read (which
processes are running output). No audio is captured, no permission prompt.

## Details
- Hold lives in `NativeAudioSink.play()`, so the daemon, the CLI's cached
  replay, the web app and the playback consumer all yield.
- `interrupt()` releases a hold; a P1 user interrupt is never blocked.
- Fallback to the output device's running-somewhere flag when the process
  list is unavailable (exceptions cannot apply there; `yield check` says
  so). Fail open when no probe answers.
- Own playback never counts: own pid, the mpv pid file, children, and any
  process whose command line (or an ancestor's) carries `auto-speech`.
- Longest hold 180 s then drop by default; `after_max_wait = "play"`
  plays anyway. Reasoning in
  [ADR-015](../decisions/ADR-015-sound-yield.md).
- Doctor validates `sound-yield.toml`; daemon `status` reports
  `sound_yield.holding` and the last hold's outcome.
- Also in this release (landed on `main` before this change): the unified
  `auto-speech` CLI dispatcher and the seven-tool MCP server.

## Also fixed
- Tests and development daemons are isolated from the live service: every
  runtime path follows `AUTO_SPEECH_TMP_ROOT` (default `/tmp`), the test
  runner uses a private directory and socket per run, and
  `tests/test_state_paths.py` proves it.

## Upgrade notes
- `uv sync` is not needed: no dependency changed.
- Restart the narrator daemon once so the running process picks up the
  new sink: `auto-speech narrate stop` (it restarts on the next request).
- `bash setup/install-plugin.sh --with-extras` adds `/auto-speech-yield`.
