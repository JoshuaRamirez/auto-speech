# auto-speech v0.5.0 — the desk is named only when the speaker changes

**Date:** 2026-10-18 · **Baseline:** `v0.4.0` · **Commits:** `e0973ff` (tests first), `b4658a0` (speaker module and daemon), `23218d8` (CLI, MCP, config) plus the release-notes commit,
merged to `main` by a `--no-ff` merge of `feat/speaker-change` · **Tests:** `tests/run_all.sh` 55 test files ran, 0 failed, under the isolated runner with the caller's Claude Code session cleared

## What changed for you

**One desk talking is heard as one voice.** Until now every desk opened
every line with its own name, so a working conversation with the Master
Desk said "Master Desk" on each line. Now a line opens with **"<desk>
here,"** only when the desk speaking is not the one you last heard, or
when the last line was more than fifteen quiet minutes ago. A change of
desk is always named, so you know who is talking exactly when that
changes (your 19:06).

| Surface | How |
|---|---|
| CLI | `auto-speech speaker status`, `on`, `off`, `gap <seconds>`, `name <session> <name>`, `forget <session>`, `who [session]` |
| MCP | `speaker(action=…, seconds=…, session_id=…, name=…)` |
| Slash | `/auto-speech-speaker …` (extras) |
| Config | `~/.config/auto-speech/speaker.toml`, `[speaker]` and `[speaker.names]` |

**Where the names come from.** The desk agents' notes: each note's
`session:` maps to its `name:` ("Master Desk") or, failing that, the
note's file name ("Aspen Desk", "Development Desk", "Clerk - Desk"). A
personal note is never read into the map. A session no note names is
announced as "Another desk"; `speaker name <session> <name>` names it by
hand, and that wins over the notes.

**What does not change.** A line that already opens with its own name is
not doubled. A line with no session (a plain shell, not Claude Code) is
spoken exactly as sent. A line held for your music and set aside on the
missed list never counts as heard, so the next line from that desk still
names it. Cached audio keeps its words and gets the name as a short clip
in front.

**Every speak path now carries its session**: the CLI and `speak.py`
from `CLAUDE_CODE_SESSION_ID`, the MCP `speak` tool from the call or its
own environment, replays and narration too.

## Under the hood

- `plugin/scripts/python/speaker.py`: `DeskNames` (notes → names,
  re-read every 30 s, personal notes skipped, config names win),
  `SpeakerSettings` / `SpeakerStore` (`speaker.toml`), `Announcer` (the
  rule: last session heard and when; prefix on a change or after the
  quiet gap; self-announced lines not doubled; only a heard line moves
  the speaker), `run_action` (the shared verb).
- `narrator_service.py`: the plan is made in `_speak` from the item's or
  the narration's session; synthesized text carries the prefix; a cache
  hit or `play_cache` goes through `_play_cached`, which plays the
  "<name> here." clip (synthesized once per name under the state dir)
  first; `_play_item` reports whether the line was heard; `status` reply
  carries `speaker`.
- `cli.py` (`speaker` subcommand; `speak` defaults the session from the
  shell), `speak.py` (same), `mcp_server.py` (`speaker` tool; `speak`
  takes `session_id`, else the server's own; replays carry it),
  `config_validation.py` (`[speaker]`, `str_map` kind).
