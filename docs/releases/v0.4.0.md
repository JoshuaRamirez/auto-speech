# auto-speech v0.4.0 — nothing held is ever dropped: the missed list

**Date:** 2026-10-18 · **Baseline:** `v0.3.0` · **Commits:** `2018602..HEAD`,
merged to `main` by a `--no-ff` merge of `worktree/missed-list` · **Tests:** `tests/run_all.sh` 53 test files ran, 0 failed, under the isolated runner with the caller's Claude Code session cleared

## What changed for you

**A line auto-speech held for your music is never lost any more.** In
v0.3.0 a line held longer than three minutes was dropped; after a long
listen you could miss twenty desk lines without a trace. Now every held
line is on the **missed list** from the moment it is held. When the sound
stops, lines younger than three minutes still play by themselves; older
ones do not pile up and play late, line by line: they stay on the list.

| Surface | How |
|---|---|
| CLI | `auto-speech missed`, `missed --play`, `missed --clear` |
| MCP | `missed(action="list" \| "play" \| "clear")` |
| Slash | `/auto-speech-missed [--play\|--clear]` (extras) |

`missed` shows what you have not heard, oldest first, with when it was
asked for, why it is on the list (longest wait, stale backlog,
interrupted, daemon restarted, or still held) and the text. `--play`
re-speaks the missed lines in that order, over whatever else is playing,
and each leaves the list once it has played. `--clear` forgets them.

**The three-minute wait is now counted from the ask**, so a line that
waited behind an earlier hold is not held for another three minutes of
its own, and the list fills in step with what you are missing.

**`after_max_wait` is gone** from `sound-yield.toml`: there is no drop
and no play-anyway. An old file with the key still loads; `yield status`
says the key is ignored.

## Details
- The hold still lives in `NativeAudioSink.play()`; past the longest wait
  it raises `PlaybackYielded` and the daemon puts the line on the list.
  `play(hold=False)` skips the gate for an explicit replay.
- The daemon keeps the list (`missed_speech.py`): a held line is written
  when the gate calls back at hold start; a played line is removed; a
  line set aside is kept with its reason and the apps that were playing.
  Held lines left behind by a daemon that stopped are settled as missed
  on the next start.
- Stale-backlog rule, in the daemon before synthesis: a line queued before
  the last hold ended and older than `max_wait_seconds` is set aside. A
  line with no hold since it was queued plays however old it is.
- Replay goes through the daemon as P2 `speak` (or `play_cache` for
  cached audio) with `missed_id` and `hold=false`; the daemon removes the
  line once it has played.
- The file is `~/.local/state/auto-speech/missed.json`
  (`AUTO_SPEECH_MISSED_FILE`), written atomically under a file lock, so
  the daemon and a `--clear` never lose each other's change.
- Reasoning for the threshold and the order:
  [ADR-015](../decisions/ADR-015-sound-yield.md).

## Upgrade notes
- `uv sync` is not needed: no dependency changed.
- Restart the narrator daemon once, while nothing is queued or playing,
  so the running process picks up the missed list: `auto-speech narrate
  stop` (it restarts on the next request).
- `bash setup/install-plugin.sh --with-extras` adds `/auto-speech-missed`
  (23 extras links).
