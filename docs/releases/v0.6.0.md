## What changed for you

**A silent open stream no longer holds your updates.** From about 19:20
on 2026-10-18 you heard nothing: Antigravity's helper kept an output
stream open while making no sound, Core Audio reported it as running
output, and every line was held and then set aside as missed, fourteen in
all ("I'm not hearing any updates out loud", 19:33). Core Audio can say
that an app is running output, not whether that output is silent, and the
only way to read a level is a process tap, which captures audio and asks
for a new permission; the Desk ruled that out (19:45).

So the rule changed: **sound holds speech only when a player app makes
it.** The players are the apps you listen to: Music, TV, Podcasts,
QuickTime Player, Safari, FaceTime, Spotify, VLC, IINA, mpv, afplay,
Chrome, Arc, Edge, Firefox, Brave, Zoom, Teams, the ChatGPT app and the
Claude app, plus whatever you add. **An unknown app's open stream never
holds.** If a new app's sound is spoken over, `auto-speech yield check`
shows it as "not on the players list" and `yield player-add <app>` fixes
it. Chrome stays a player: its helper with the mic and speaker open may
be your ChatGPT voice session, the long listen the hold was asked for.

| Surface | How |
|---|---|
| CLI | `auto-speech yield hold-for players|any`, `player-add <apps…>`, `player-remove <apps…>`, `player-reset`; `status`, `check` |
| MCP | `sound_yield(action="player-add", apps=["Slack"])`, same actions |
| Slash | `/auto-speech-yield …` (extras) |
| Config | `~/.config/auto-speech/sound-yield.toml`, `[sound_yield] hold_for`, `players` |

**What does not change.** The hold, the 180 s longest wait, the missed
list and its replay order (ADR-015); the exception list, which still
subtracts from the players; the switch. `hold_for = "any"` restores the
old rule for anyone who wants every app to hold.

The reasoning is in [ADR-017](../decisions/ADR-017-players-list.md).
